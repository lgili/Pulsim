## Phase 4D: Textbook-style ground rail (follow-up to user feedback "ainda está horrível")

User still found the boost area unreadable after Phase 4C — Cout and Rload remained diagonal because vout and gnd were at different `(x, y)` positions; Q1's gate connection to Vgate was invisible (zero-length wire between two anchors at the same node); the gate driver `Vgate` floated at the canvas west edge thanks to the `source_pos` prior pinning `gate_pwm`.

- [x] 4D.1 Ground rail routing in [`layout.py`](../../../python/pulsim/schematic/layout.py): new `_route_ground_rail()` step runs after parallel separation. Every device with a gnd-terminal has that anchor moved to `(its_device_x, rail_y)` where `rail_y` is the post-lift ground position. 2-terminal gnd devices become **clean vertical bars** from their non-gnd terminal straight down to the rail. The star-wire emission then connects all gnd-terminals at `rail_y` — forming a continuous horizontal ground rail along the canvas south. Asserted by `test_ground_rail_routes_all_gnd_terminals_to_same_y`.
- [x] 4D.2 Parallel gnd-pairs fan out in x on the rail: groups of 2-terminal devices sharing the same `non_gnd_node ↔ gnd` pair get a per-device perpendicular offset (`±18 mm` step). Cout and Rload across `vout ↔ gnd` become two side-by-side vertical columns at `vout.x ± 9 mm`, both ending on the rail. Asserted by `test_parallel_gnd_pair_becomes_side_by_side_vertical_bars`.
- [x] 4D.3 `_separate_parallel_devices` now takes a `ground_id` argument and skips any pair containing ground; the gnd-rail routing handles those exclusively. Non-gnd parallel groups (e.g. snubber R+C across two internal nodes) still snap to the dominant orthogonal axis as before.
- [x] 4D.4 Gate-driver suppression of `source_pos` prior: voltage sources that drive the *control input* of a switch (terminal 0 of MOSFET / IGBT / vcswitch) no longer get pinned to the canvas west edge. The pin was useful for "main input" voltage sources (`Vbus`, `Vac`) but harmful for gate drivers, which it pulled miles away from the switches they control. `_compute_node_positions` now builds a `control_nodes` set and skips the source_pos pin for any node in it. The spring layout keeps gate drivers adjacent to their target switch.
- [x] 4D.5 Gate-anchor stub relocation: for 3-terminal switches, terminal 0 (gate) is repositioned to `(placement.x − 8 mm, placement.y)` after placement. Without this, the gate-terminal anchor sits at the gate node's spring position — and when another component (e.g. Vgate) is on the same node, the wire from one to the other is zero-length (they're at the same coord) and not rendered. With the stub, the wire is a non-degenerate line connecting the switch's symbol-edge to the gate-driver — visible, correct, and reads as a "gate trace" in the schematic.
- [x] 4D.6 Boost PFC re-render confirms: bridge with vac_a/vac_b on the sides feeding rect_pos at the top (no gnd touching), lower bridge diodes vertical down to the rail (D3, D4 at the rail bottom), L1–D1 horizontal top rail, Q1 vertical between sw_node and rail with a visible diagonal wire to Vgate (now positioned to the right of the boost stage near Q1), Cout || Rload as two side-by-side vertical bars between vout and rail. ## Phase 4E: Adopt ELK (Sugiyama + orthogonal routing) as the default layout backend

User feedback after Phase 4D remained "está horrível" — the hand-rolled force-directed + templates pipeline can't deliver textbook-quality schematics because it optimizes for graph-aesthetic properties (edge length, node separation) instead of EDA-aesthetic properties (left-to-right power flow, orthogonal wires, port-aware rotation, layered placement). After researching the state-of-the-art in 2026 (lcapy, ELK, netlistsvg, Graphviz, SKiDL, LLM approaches), the only mature engine that does what we need is the **Eclipse Layout Kernel** (ELK) via its `elkjs` JavaScript distribution — the same engine that powers `netlistsvg` (the standard digital-schematic renderer for Yosys output, ~800 GitHub stars, MIT) and `d3-hwschematic`.

- [x] 4E.1 New file [`python/pulsim/schematic/elk_bridge.js`](../../../python/pulsim/schematic/elk_bridge.js) — thin Node.js bridge that reads an ELK graph JSON from stdin, runs `new ELK().layout(graph)`, and writes the laid-out result to stdout. Pinned via `package.json` at the repo root (`elkjs ^0.11.1`).
- [x] 4E.2 New file [`python/pulsim/schematic/elk_backend.py`](../../../python/pulsim/schematic/elk_backend.py) — Python wrapper that:
  - builds an ELK graph from `circuit.components()` (each component → ELK node with sized box and per-terminal ports);
  - chooses port sides via heuristics (2-terminal with gnd → SOUTH/NORTH bar; 2-terminal pure → WEST/EAST flow; 3-terminal MOSFET/IGBT/vcswitch with source at gnd → gate WEST + drain NORTH + source SOUTH so the FET sits vertical with the gate driver coming in from the left);
  - applies layer constraints (voltage sources → `FIRST` layer / leftmost, resistor-to-ground loads → `LAST` layer / rightmost) so the layered Sugiyama algorithm honors power-flow direction;
  - sets `elk.algorithm: layered`, `elk.direction: RIGHT`, `elk.edgeRouting: ORTHOGONAL`, plus spacing options sized for our schemdraw render scale;
  - subprocesses to `node elk_bridge.js`, parses the laid-out JSON back, and emits a `SchematicLayout` with terminal anchors at the ELK port positions and wires carrying ELK's orthogonal bend points in `Wire.path`.
- [x] 4E.3 [`render.py`](../../../python/pulsim/schematic/render.py) `_draw_wire` updated to draw the polyline through `Wire.path` (one `elm.Line` per consecutive segment, with duplicate-point dedup) instead of a single straight line from terminal-to-terminal. The orthogonal bend points emitted by ELK are now preserved in the rendered SVG/PNG.
- [x] 4E.4 [`compute_layout`](../../../python/pulsim/schematic/layout.py) now delegates to `compute_layout_elk()` by default. The legacy in-tree spring + templates + parallel-pair + ground-rail pipeline is preserved as an opt-in fallback via the environment variable `PULSIM_SCHEMATIC_BACKEND=spring` (used in Node-less CI environments and by the 6 legacy regression tests below).
- [x] 4E.5 `python/CMakeLists.txt` extended to also copy `*.js` files under `pulsim/schematic/` into the build tree — `elk_bridge.js` now ships alongside the Python modules.
- [x] 4E.6 `.gitignore` extended to exclude `node_modules/` and `package-lock.json` at the repo root.
- [x] 4E.7 6 legacy regression tests (asserting the spring backend's geometry — canvas-south ground anchors, voltage source x < canvas.width/4, bridge diodes in 4 quadrants, ground-rail single-y, parallel-pair x-offset) tagged with a new `_SPRING_ONLY` skipif decorator. They skip when ELK is active and run when `PULSIM_SCHEMATIC_BACKEND=spring`. Both backends remain fully tested: 46 passed / 6 skipped on ELK; 30 passed on the spring fallback; **0 regressions** in the wider Python suite (407 passed total).

## Phase 4F: Adopt netlistsvg + analog skin as the default render backend

User feedback on Phase 4E was "cara ficou uma merda igual" — ELK with our hand-rolled port/skin mapping still produced output with large empty regions, scattered bridge diodes, and components rendered as plain rectangles instead of proper analog symbols. We then tested `netlistsvg` (the production schematic renderer used by the Yosys / openlane ecosystem — 800+ GitHub stars, MIT-licensed, internally uses ELK with carefully-tuned options) with its purpose-built **analog SVG skin** that ships proper graphical primitives for resistors, capacitors, inductors, diodes, voltage sources, ground symbols, etc. The output is dramatically better — real analog schematic quality. The user confirmed: "esta é a qualidade que queremos".

- [x] 4F.1 New file [`python/pulsim/schematic/netlistsvg_backend.py`](../../../python/pulsim/schematic/netlistsvg_backend.py) — Python wrapper that:
  - converts `Circuit.components()` to Yosys-format JSON (the netlistsvg input format);
  - assigns each non-ground electrical net a unique integer "bit" and emits a *private* `gnd` cell per ground-terminal so each device gets its own ground symbol (standard schematic convention);
  - maps Pulsim kinds to netlistsvg analog-skin **aliases** — `r_v`, `c_v`, `l_h`, `v`, `i`, `d_h`, `transformer_1p_1s` (the bug-that-bit-us: netlistsvg matches against `<s:alias val=...>`, NOT against `<s:type>` element names; first PoC fell back to `generic` boxes because we used full names);
  - 3-terminal switches (MOSFET / IGBT / vcswitch) fall through to `generic` because the analog skin has only bipolar transistors; proper symbols will land in the `add-pulsim-analog-skin` follow-up;
