## Why

A power-electronics group is using AI coding assistants (Claude Code,
Copilot, Cursor) to write Pulsim 2.x scripts, and the assistants get
the API wrong in ways that run without error:

- **They invent calls.** Models were trained on Pulsim 1.x and on other
  simulators. Until this week the 2.0 tutorials had broken calls too, so
  the published docs did not correct them.
- **They cannot see signatures.** `pulsim._pulsim` is a pybind11 module.
  `inspect.signature(pulsim.CircuitBuilder.add_sine_voltage_source)`
  raises `ValueError`, and no `.pyi` ships. The signature exists only in
  the first line of `__doc__`. IDEs and agents therefore guess argument
  order. For example, `add_sine_voltage_source(name, n_pos, n_neg, v_dc,
  v_amplitude, frequency, phase=0.0)` takes `v_dc` FIRST.
- **They get the semantics wrong with confidence.** Several behaviours
  are non-obvious. PWL diode `V_th` is a commutation threshold, not a
  forward drop. A plain `.mean()` over `engine='auto'` samples is biased
  by -21 % to -52 %. `SwitchStateMask(1)` means one switch, OFF.
  `tol_newton_dx` is absolute and must not be loosened. A micro-ohm
  ground bond is the wrong way to reference an isolated secondary. Each
  of these produces a plausible wrong number, not an error.

Measured on this branch (2026-11-06), stubs fix the signature problem.
A `.pyi` generated with pybind11-stubgen, checked by mypy, rejects
`add_sine_voltage_source("V", "a", "gnd", amplitude=10.0,
frequency=50.0)` ("did you mean `v_amplitude`?"). The same stub cannot
be shipped as generated, though. Five `CxxBlockChain` signatures do
not parse as Python. The stub imports `pybind11_stubgen`. Some defaults print as
`0x…` object addresses, and the attributes the Python layer attaches to
`SimulationResult` (`engine_used`, `v`, `i`, `power`) are missing.

Semantics need prose that is matched to the installed version and that
cannot rot. Docs that are not executed have already rotted once.

## What Changes

- **NEW: typed stubs.** Commit `python/pulsim/_pulsim.pyi`, generated by
  a pinned `pybind11-stubgen` through `scripts/generate_stubs.py`. The
  script post-processes the output and merges a hand-written overlay
  for the members the Python layer attaches. It also ships
  `python/pulsim/py.typed`. Both go into the wheel and into the
  `build/python` package copy.
- **NEW: stub freshness checks.** A dependency-free pytest compares the
  stub with the runtime module: names, parameter names, order and
  defaults. It runs on every CI leg. One designated CI job also
  regenerates the stub and diffs it byte for byte.
- **FIX (bindings only): signatures must render as valid Python.** Add
  pybind class forward declarations so property types stop printing as
  `pulsim::topology::Graph`. Add `py::kw_only()` where a required
  argument follows an optional one. Give `py::arg_v` printable defaults
  in place of `0x…` reprs. Use `std::optional` for `None` defaults. No
  kernel change, and no positional call that works today breaks: every
  in-repo caller of the affected `CxxBlockChain` methods passes
  keywords (`python/pulsim/blockchain.py:331`, `:415`).
- **NEW: in-package usage guide.** `python/pulsim/AI_GUIDE.md` is shipped
  in the wheel. It is printed by `python -m pulsim.guide` and returned by
  `pulsim.ai_guide()`. The name was checked against `dir(pulsim)` and
  clashes with nothing. The output is prefixed with the installed
  `pulsim.__version__`. The guide is short (≤ 32 KiB) and prescriptive:
  the verified 2.x idioms, the semantic traps listed above, and how to
  verify a result physically.
- **NEW: `docs/llms.txt`.** It follows the llms.txt convention and
  points to the guide and the key docs. The MkDocs build copies it to
  the site (served at `…/Pulsim/<version>/llms.txt`), and the guide is
  rendered as a site page through `pymdownx.snippets`, from one source.
- **NEW: executable documentation.** A pytest module runs every
  `python` block in the guide, `README.md`, `docs/getting-started.md`
  and `docs/tutorials/*.md`. Blocks share one namespace per file and
  run in order. Each block's printed output is compared with the
  following expected-output block, with tolerance on numbers. The
  module is marked `doc_snippets` and runs in the default CI
  invocation. Measured cost today: 6.2 s for all eight files, 5.0 s of
  it in Tutorial 06.
- **FIX: in-package text that contradicts the guide.** The guide is not
  the only text an assistant reads. Docstrings flow into the stubs.
  `add_three_phase_vsi` documents `V_f` as "Forward drop (V)"
  (`python/pulsim/topology.py:273`) but passes it as `V_th`.
  `p.catalog()` recommends "small (1µΩ) values to tie floating subnets"
  (`python/pulsim/discovery.py:55`). `add_mosfet`'s binding docstring
  calls `V_F` a body-diode drop. All three are reworded.
- **NEW: the unknown-attribute hint points to the guide.** The PEP 562
  `__getattr__` message that fires when code invents a `pulsim.X` name
  will name `python -m pulsim.guide`.

## Impact

- Affected specs: `python-bindings` (typed stubs, signature hygiene),
  `usage-guide` (new: guide, accessor, CLI, content rules, llms.txt,
  text consistency), `executable-documentation` (new: snippet
  execution).
- Affected code:
  - `python/bindings.cpp`: binding-only signature fixes (forward
    declarations, `py::kw_only`, `py::arg_v`, `std::optional`
    defaults, the `add_mosfet` docstring).
  - `python/pulsim/_pulsim.pyi`, `python/pulsim/py.typed`,
    `python/pulsim/AI_GUIDE.md`, `python/pulsim/guide.py`,
    `python/pulsim/_ai_guide.py` (all new).
  - `python/pulsim/__init__.py`: export `ai_guide`, update the
    `__getattr__` hint.
  - `python/pulsim/topology.py`, `python/pulsim/discovery.py`: wording.
  - `python/CMakeLists.txt`: the build-tree glob copies `*.md` and
    `py.typed`.
  - `scripts/generate_stubs.py`, `scripts/stubs_overlay.pyi` (new).
  - `python/tests/test_stubs.py`, `python/tests/test_ai_guide.py`,
    `python/tests/test_doc_snippets.py` (new).
  - `pyproject.toml`: register the `doc_snippets` marker; add
    `pybind11-stubgen` (pinned) and `mypy` to the `dev` extra.
  - `docs/llms.txt`, `docs/ai-guide.md` (new), `mkdocs.yml` nav, and
    small annotations in `README.md`, `docs/getting-started.md` and the
    tutorials (`<!-- doctest: requires=matplotlib -->`).
  - `.github/workflows/ci.yml`: one leg installs matplotlib and runs the
    stub `--check`. `.github/workflows/publish.yml`: the wheel smoke
    test also runs `python -m pulsim.guide` and asserts that `py.typed`
    and `_pulsim.pyi` ship.
- Sequencing: the guide's charge-balance example uses a `V_th > 0`
  diode and asserts that the balance closes. That holds only once the
  per-sample switch-state record (`fix/v2-diode-record`) is merged, so
  this change is implemented on top of it (task 0.1).
- No breaking change to any documented call. Positional calls to the
  internal `CxxBlockChain.add_sum` / `add_inverse_clarke` /
  `add_pwm_generator` / `add_flux_mras_observer` /
  `add_sliding_mode_observer` past the first defaulted argument become
  keyword-only. None exist in the repository.
