simulator's piecewise-linear laws exactly in mpmath (method: the module docstring).

`ideal_switch_flip_evidence.py` (R_on = 0 switches and diodes, V_f = 0, g_off kept).

observables, every event two-sided: the right limit one ulp after the left) with a
`.json` record. They do not replace the harness's references.

jumps, the sources' impulsive work minus the stored-energy change (E dx = A s).

### What "the stored reference's error" means here

The harness stores no reference trace. `differential_runner.reference` runs
trbdf2 at rtol 1e-8 (else pwl dt/4) at grading time. Its error against the
truth needs that engine run, so every "reference error" below is **not
computed**. What the truth gives without an engine run:

- `floor`: the score a perfect fixed-step trace gets on the netlist dt grid.
  A pwl cell close to it disagrees through the measure (linear interpolation
  across commutations), not through the engine.
- The triangle bound: |cell vs truth - cell vs reference| <= reference vs truth.
  A grading run with `exact_truth.py compare` gives the last term.

### Adopting the truths (harness maintainer)

1. Keep `benchmarks/truth/` as is. Each `<stem>.csv.gz` has `time` plus the
   harness observables. Every event is stored two-sided: the right limit sits
   one ulp after the left. `<stem>.json` holds events, integrals and checks.
2. In `differential_runner.reference(case, cols, tol)`, first look for
   `benchmarks/truth/<yaml stem>.csv.gz`. If present, return
   `("exact truth", (t, {c: y[c]}, None))`. The third slot is the switch
   record; `diagnose` must accept None for the reference, or derive it from
   the `.json` events.
3. Grade with the existing `compare` (unchanged measure). The truth's own
   uncertainty is `u stored` in the table above. It is below the pwl tol/10
   (0.002) on every solved circuit, and below the trbdf2 / dsed tol/10 (1e-4)
   except on ll06 (7.7e-4) and ll09 (4.6e-4), where fast g_off decays fall
   between stored points. There, or for any cell needing more, grade with
   `exact_truth.py compare <yaml> <trace.csv>`: it evaluates the truth exactly
   at the trace's own times, so the stored grid adds nothing.
4. CSVs are committed for the eight circuits (both forms) and the circuits
   whose cells disagree; for the rest only the `.json` record is committed
   (size). `exact_truth.py truth <yaml>` regenerates any of them in seconds to
   minutes.
5. Re-freeze `known:` / `known_err:` in the release that changes the numbers.
   Cells move by at most the old reference's error. A cell whose score is near
   `floor` is a measure limit: give it an `exclude` window or an event-aware
   grid, do not chase it in the engine.
6. Regenerate with `exact_truth.py truth <yaml> --form conductance|ideal`, then
   `exact_truth.py report`. Check that the 30- vs 60-digit column stays below 1e-12 (it is 4e-13 at worst: active_clamp_forward).

### The two disagreements between converged tools

`ideal_switch_flip_evidence.py` (phase0) refines trbdf2 (by rtol) and
pwl+restart (by dt) on each ideal twin. Each tool converges on its own, yet
the two end apart (`e_cross`, symmetric measure). The cache holds metrics
only, no traces. So which tool is wrong is **not computed** here: that needs
the two finest traces through `exact_truth.py compare <yaml> <trace> --form ideal`.

Read: neither gap is a sampling artefact. Every floor is below `e_cross`,
and neither ideal waveform jumps (no impulsive event). Two converged tools
cannot both be within e_cross/2 of the truth: at least one converges to a
wrong ideal-twin waveform. `compare` against `<stem>.ideal.csv.gz` names it
with one run of each finest setting. A cheap cross-check: the ideal truth
sits 1.3e-4 (diode_rectifier) and 1.2e-3 (flyback) from the conductance
truth, so a tool farther than that from the conductance reference is the
wrong one.

### Mode non-uniqueness

No solved circuit has an event with two strictly consistent modes. The
weak case appears only in ideal twins where an ideal diode sits
antiparallel to an ideal switch that is ON (full_bridge_dc). Both are
0 V branches in parallel, so the split of their current is not defined.
The node voltages and the waveform are unique. The tool keeps the diode
OFF, pinned at v = 0. An engine that splits the current differently is
not wrong on any graded column.
